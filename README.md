# dsh-settings-groups

给 DeepSeek Harness 的设置面板侧栏做**分组 + 排序**：分组标签压到 26px、展开收起带下拉缩放动画，条目可以在分组和未分组之间随意拖。

> 起因：`dsh-settings-nav-organizer` 能折叠分组，但**顺序写死**（跟着台账 order 走）、组内也调不了序、分组行还是跟条目一样高的整行按钮。这个插件只做补不上的那三件事。

## 功能

| 需求 | 这个插件怎么做 |
| --- | --- |
| **自由配置排序** | 分组的先后、组内条目、未分组条目，全都靠拖拽调；顺序存 `localStorage`，重启不丢。 |
| **分组 / 未分组，随意派** | 把条目拖到某个分组标签上 = 归入该组；拖到「未分组」上 = 移出。管理页也能改（下拉 + 上下箭头 + 拖行）。 |
| **搜索** | 导航顶部一个 26px 的搜索框，输入即过滤（核心项一起过滤）；收起的分组里命中项也会露出来，不用先手动展开。隐藏项不参与搜索。 |
| **隐藏设置项** | 用不上的入口可以藏起来 —— 导航里彻底不出现，配置留着；管理页的「已隐藏」区能一键放回来。 |
| **记住收起状态** | 哪个分组是收着的、未分组收没收，都存下来；关掉 DSH 重启、换窗口、清缓存，回来还是原样。 |
| **分组标签要小、要有动画** | chip 高 **26px**（宿主条目是 40px），12px 字、**粗体（700）**、浅灰、悬停才亮。箭头是**细线 chevron**（`>` → `v`，两条边框拼 L 形转 -45° 画的），展开时转 90° + 放大 15% + 提亮。展开/收起**用 `@keyframes` 而不是 `transition`**（`display:none` 恢复的那一帧，浏览器认为元素刚出生、没有前值可插值，transition 直接不跑），同时动四层：**透明度 + `scale(.88) translateY(-8px)` + `filter: blur(4px)` + 真实高度塌陷**，260ms `cubic-bezier(.4,0,.2,1)`，组内条目逐个错开 26ms，小三角带回弹转 90°。 |

附带：分组可重命名 / 删除（删除后条目回未分组，条目本身不动）、一键重置、总开关（关掉后导航**完全**恢复宿主原生平铺）。

**不做**：AI 自动分类、闲置插件清理、插件启停管理、搜索框 —— 那是另一个插件的活儿。

## 配置存在哪

**两处，双写。**

| 位置 | 作用 |
| --- | --- |
| `localStorage["dsh.settingsGroups.v1"]` | 同步写入，立即可读；界面渲染先看它 |
| `~/.dsh/dsh-settings-groups.json` | 宿主端落盘（`index.js` 注册 `/api/dsh-settings-groups/config` 路由，只允许回环访问） |

为什么两处：localStorage 是按**来源**分的，换了 origin、清了缓存、换了窗口分区就是另一份，光靠它守不住「关了 DSH 再开还是原样」。磁盘那份是硬保障。

两份配置都带 `updatedAt`，启动时对一次账：**磁盘比本地新就用磁盘的**（比如清过缓存），本地比磁盘新就把它推上去。不会拿旧数据倒灌，也不会互相覆盖。

宿主端那条路由没加载时（比如只改了客户端还没重启 DSH），自动降级成纯 localStorage，功能照常。

### 直接改文件让 AI 帮你配

`~/.dsh/dsh-settings-groups.json` 长这样（`_labels` 和 `_readme` 只是注释，不参与逻辑）：

```json
{
  "_readme": "改完存盘，设置面板开着的话 5 秒内生效。",
  "v": 1,
  "updatedAt": 1761111111111,
  "enabled": true,
  "folded": false,
  "groups": [
    { "id": "g1", "name": "开发工具", "entries": ["dsh-read-aloud", "dsh-commandcode"], "open": true }
  ],
  "loose": ["dsh-meme"],
  "hidden": [],
  "coreExtra": [],
  "_labels": {
    "dsh-read-aloud": "语音朗读",
    "dsh-commandcode": "Command Code",
    "dsh-meme": "表情包"
  }
}
```

- `groups[].entries` / `loose` / `hidden` 里填 `_labels` 的**键**（那串 id），不是中文名
- `open: false` = 这一组收起；`folded` = 未分组那行收不收
- 手改**不用管 `updatedAt`**：插件靠内容比对，不靠时间戳
- 改完存盘，设置面板开着的话 **5 秒内自动跟上**；没反应就点管理页的「从磁盘重载」
- 一个条目只能出现在 `groups` / `loose` / `hidden` 其中一处，重复了以 `hidden` 为准
- `coreExtra`：把额外的设置页 id 当作**宿主官方入口**（固定在顶部、不可分组）。DSH 以后加新内置页时，把它的 id 加进这个数组就不用改代码

## 顺带接管了设置面板「可拖可调」

原先给设置面板加「侧栏拉宽 / 面板拖动 / 四边四角缩放」的是本机补丁 `dsh-settings-panel-tweak`，**打在 `dsh-settings-nav-organizer` 的 `client.js` 里**。既然本插件要顶掉它，那份能力也一并接过来了，否则一停旧插件，侧栏就变回 188px 写死、拉不动。

- **切页过渡**：点左侧任意设置项，右侧内容区淡入 + 从 `blur(7px)` 拉清楚（300ms）。宿主渲染的内容区换页没有可过渡的前后值，所以用 `animation` 播一次；靠左侧按钮 `aria-current` 换人来感知切换，动画播完自动回到无 `filter` 状态，不会常驻合成层
- 侧栏右缘分隔条拖动改宽度，双击复位（复位带 0.28s 过渡滑回去；拖动瞬间不加过渡，否则跟手会变成追着跑）
- 内容区 header 可拖整个面板（落在按钮/输入框上不抢手势），双击复位
- 面板四边 + 四角缩放（默认比宿主大一整圈），双击复位
- 尺寸/位移仍存 `localStorage["dsh.settingsPanelTweak.v1"]` —— **和旧补丁同一个键**，之前调好的宽度和位置直接延续

### 「装上之后设置变糊」是怎么回事（已修）

旧补丁给面板挂了一条**常驻**的 `will-change: transform`。这会把这个设置面板在整个生命周期里都提升为 GPU 合成层，而合成层里的文字不再走 subpixel antialiasing（次像素抗锯齿），只剩灰度抗锯齿 —— 看起来就是整体发虚、变细，在 Windows 的 125% / 150% 缩放下尤其明显。

现在改成**按需提层**：只有真正按住分隔条 / 标题栏 / 缩放手柄时才加 `will-change`，松手立刻撤掉。平时面板的 `will-change` 是 `auto`，文字回到正常渲染。

> 另外：只要你把面板**拖动过**（位移非 0），它就必须留在合成层上（`transform` 本身就意味着提层）。双击标题栏复位到居中，就能回到完全清晰的状态。

## 和 dsh-settings-nav-organizer 的关系

**旧分组会自动搬过来**：首次启动时如果新配置里一个分组都没有、而 `dsh.settingsNavFold.v1` 里有旧分组，插件会一次性转换过来（标 `migratedV1`，之后不再重复，删光了也不会被旧数据复活）。

两者都会改写设置导航的 DOM，**同时启用会互相打架**。本插件检测到旧插件在跑（它必插一条 `style[data-settings-nav-fold="1"]`）时**自动退让**，不碰导航 DOM，只在管理页顶部挂一条警告。

切换步骤：

1. 打开设置 → **插件管理** → 把 `dsh-settings-nav-organizer` 禁用（或 `dsh plugin --profile desktop remove dsh-settings-nav-organizer`）；
2. 重启 DSH；
3. 设置 → **分组管理**（新的这一页）。

想回退：把旧插件加回来 / 启用，本插件会自动让位，两边配置各自独立、互不覆盖。

## 安装

本机开发版走 `link:` 接进 profile 的 **bundle 层**（不写宿主 `cordis.patch.yml`，那条通道会被别的插件整文件回写削掉）：

```sh
node scripts/profile.mjs install --profile desktop
node scripts/profile.mjs check   --profile desktop   # 退出码 0 = 接线完整
node scripts/profile.mjs uninstall --profile desktop
```

装完**重启 DSH**（宿主端要加载新插件）。只改 `client.js` 的话，窗口里 `Ctrl+R` 就够。

## 使用

### 导航里

- 点分组标签 → 展开 / 收起（带动画）
- 拖条目 → 落到分组标签上归组；落到某条目上按上下半区插入前后；拖到「未分组」上移出
- 拖分组标签 → 改分组之间的先后
- 没有建过分组时不会注入任何标签，导航跟原生一模一样

### 管理页（设置 → 分组管理）

- **新建分组**：输入名字回车
- **分组卡**：`↑ ↓` 调组序、`重命名`、`删除分组`（条目回未分组）
- **组内条目**：拖行可调序、`↑ ↓` 精调、`移出` 回未分组
- **未分组条目**：拖到任意分组卡上即归组，或从 `加入分组 ▾` 下拉里选
- **隐藏**：每行末尾的 `⊘`；也可以把条目拖进「已隐藏」卡片
- **已隐藏**：列出所有藏起来的条目，点「取消隐藏」放回未分组末尾
- **重置全部配置**：清空分组、排序与隐藏

一个条目同时只处在一种状态：**某个分组 / 未分组 / 已隐藏**，三者互斥 —— 拖进分组就自动从隐藏里出来，藏起来就自动退出分组。

藏掉的如果是当前正在看的那一页，插件会先帮你跳回「通用设置」，免得内容区停在一个导航上已经不存在的页面上。

宿主的官方入口（账号与余额 / 通用设置 / 模型 / 插件 / Agent 预设）**固定在最上面**，不参与分组 —— 它们不是插件贡献，藏进分组里没有意义，也容易把「账号与余额」这种常用页埋掉。

## 原理

设置导航不是 Slot，是宿主内部渲染的列表，所以插件只能：

1. 读 `ctx.slots.entries("settings.section")` 台账，拿到全部设置页的 id / order / label；
2. 把分组标签按钮**注入**导航列表，并把原生按钮**移动**（不是复制）成「核心项 → 各分组标签 + 组内条目 → 未分组标签 + 其余条目」的顺序；
3. 显隐和动画靠 `data-dsg-*` 属性 + 一段样式表，**不动宿主按钮的结构**；
4. 拖拽用原生 HTML5 DnD，`drop` 时改配置再重排；
5. 用 `MutationObserver`（带风暴看门狗）跟随宿主重渲染；按钮与台账的映射走「印记 → label → DOM 顺序」三级匹配，映射错了会 `console.warn` 报出来。

停用插件时会把留在宿主按钮上的 `draggable` / `style` / `data-dsg-*` 全部抹掉，导航回到原样。

## 为什么不按 order 判断「哪些是宿主内置页」

一开始想用 `order < 30` 来识别内置页（因为内置页 order 都很小），**实测行不通**：本机就有第三方插件把设置页注册在 `order 12 / 15 / 25 / 26`。按阈值判断会把它们锁成「不可分组、不可隐藏」，比"新内置页混进未分组"难受得多。

所以用白名单 + 配置里的 `coreExtra` 扩展。DSH 真加了新内置页，把它混在未分组里看得见、也好处理，不会静默出错。

## 已知边界

- 只处理 `[role="dialog"][aria-modal="true"] > nav > div:last-child` 这个结构，宿主改版可能要跟着调。
- 分组配置双写：`localStorage` + `~/.dsh/dsh-settings-groups.json`。文件跟着 `DSH_HOME` 走，换 profile 会各存一份，互不影响。
- 分组记的是**设置页 id**。插件卸载后条目从台账消失，配置里那条会留着（重装还能回到原分组），但拖别的条目时只保留历史记录、不参与排序。
